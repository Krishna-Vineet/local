We can bundle backend and frontend together to create an app but in order to establish collection between backend and frontend we need something called IPC Renderer, it is custom made bidirectional contact method, like REST, webhooks, etc that we can use. 

Now this IPC is an electron thing, So how we will get it into the Frontend Running inside chromium? There are multiple ways:
1. we can intiate Complete electron In app window (frontend) running on chromium by doing `window.require('electron')`.
2. we can give Chromium the complete power of node itself.
But the issue in both is security vulnerabilities, as giving the complete electron Or complete node to frontend Will let hacker Get also the things like file system Os and others from the frontend itself.

So we will using a `preload.cts` file. The `cts` stands 4 common TS. We do not want this to get compiled later Combined with Normal js/ts file so we are giving it a different Extension CTS. This preload file will run when electron will be creating a window, And only the necessary functions will be sent to the windows.

To do this, we have to configure BrowserWindows web preferences as give `preload` option, pointing to our `preload.cts` file. but the path to this file will change according to if it is development Or production environment, to tackle that, i am using function `getPreloadPath()` from `pathResolver.ts`. Actually `pathResolver.ts` is a function that will give us the correct path to the preload file in both Development and production environment.

the `preload.cts` will later transpiles as `preload.cjs` will will remain seperate from other mjs (js) files.

the path of the `preload.cjs` is different in dev and prod because, we have written `"extraResources": ["dist-electron/preload.cjs"],` in `electron-builder.json` so that erectron builder also treate it seperately and store in seperate dist-electron folder outside of actual app folder after app is being build. But in development the main.js and preload.cjs are lying in same folder dist-electron.
